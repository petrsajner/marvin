# Marvin 1.6.2: automatic model startup and action feedback

## Changes

- API lifespan starts the last successfully loaded model and KV profile by default. Explicit QWEN_AUTOSTART_SERVER=0 remains available for diagnostics; manage_model=False test services never load a GPU model.
- Persist the last successful model from manual starts, switches, and ordinary agent runs. Failed loads do not replace it. Existing hardware fitting remains active.
- A desktop window reopening an existing server requests autostart, without disturbing an active task. Launcher reuse requires matching data root and application version.
- Start/restart/stop publish phase, command and original start time. Start is optimistically highlighted immediately, gently pulses through loading and returns to idle on completion. Stop remains usable during loading.
- Model panel shows server preparation/loading/stopping, elapsed time, VRAM and errors. Header reflects loading and failure; polling is every two seconds and stale pre-click requests cannot overwrite the optimistic state.
- Central request feedback covers foreground mutations and content loading, including upload, export, import, rename/move/delete, memory/settings, restore and queued task submission. A confirmation acknowledges the request, not completion of an asynchronous model task. Draft autosaves and background polling remain quiet.
- Backup progress shows incremental output, elapsed time and completion/failure. Long compression/handoff is identified as summarization in the conversation activity bar.
- Reduced-motion preference disables pulse/spinner animation while retaining visible status.

## Verification

- Workspace regression tests cover default startup, remembered model/KV, failed switch preservation, and reopening a stopped model without interrupting a task.
- tests/workspace_feedback.browser.js simulates a held startup response, readiness, failure and delayed settings save. Checks immediate UI feedback, pulse, Stop availability, success/error states. The expected HTTP 500 is the only console error from this scenario.
- Real installed-data startup on port 7861 automatically loaded Qwen Q5 with q8_0, reached ready with about 27.9/31.8 GB VRAM, and persisted last_running_model/last_running_kv. No user task was submitted as part of this check.
- Release pipeline: core tests, workspace tests, TypeScript/Vite, refreshed Czech/English manuals, PyInstaller and Inno Setup 1.6.2. Installer is built, not run over the owner's installation.
