### How the feature works

- The system prompt of every work mode asks the model to end each reply with
  `<next_step>…</next_step>`: its running guess of the user's next instruction.
- `Agent._step` hides the tag from streamed text (`NextStepStreamFilter`) and from
  saved replies (`split_next_step`).
- The latest guess is stored in `session.meta["next_step"]` and emitted as the
  `next_step` event.
- When a final reply carries no guess, the agent derives one from the task state:
  a failing check, then an unfinished plan step, then the summary's "📋" next steps.
- The composer shows the suggestion as its placeholder when the chat is idle and the
  field is empty. → or Tab takes it.

## Remaining work, in order

1. **Update the checkout.** `git pull` on `main` and confirm the tree is clean.
2. **Check with real models.** Run Marvin from this checkout with Qwen 3.8 27B and
   Flash-Next, in a Development task and in Discussion. Check that:
   - a suggestion appears when the task ends;
   - no `<next_step>` text shows in replies or progress;
   - → and Tab take it;
   - the setting hides it.

   The first request of an existing chat reads its prompt once more; that is
   expected. If a model rarely writes the tag, adjust `NEXT_STEP` in
   `harness/prompts.py` and rerun `tests/test_next_step.py`.
3. **Build.** `installer\release.bat`. It builds the frontend and manuals
   (`output\pdf`), runs `tests\test_core.py` and the unittest discovery, builds
   `Marvin.exe`, and compiles `dist\Marvin-Setup-1.20.0-Minimal.exe` and
   `dist\Marvin-Setup-1.20.0-Full.exe` (with `check_full_runtime.py`).
4. **Install.** Update the owner's installation (`%LOCALAPPDATA%\QwenHarness`) with
   the Full installer and repeat a short check from step 2 in the installed build.
5. **Offline backup.** As for 1.19.0 (`docs/distribution/RELEASE-1.19.0.md`, "Offline
   package refresh"):
   - refresh `Marvin-Offline-Backup-1.19.0` from the installation with
     `scripts\offline_backup.py refresh --backup <folder> --runtime-root %LOCALAPPDATA%\QwenHarness`
     (see `--help` for `--exclude-models` and `--quarantine`);
   - attach the new Full installer with `attach-installer`;
   - rename the folder to `Marvin-Offline-Backup-1.20.0`;
   - run `verify`.
6. **Stage and record.**
   - `powershell -File scripts\package_distribution.ps1` stages `dist\release-1.20.0`
     with `SHA256SUMS.txt`.
   - `python scripts\release_manifest.py --commit <application build commit>` writes
     `docs/distribution/release-1.20.0.json`.
   - Write `docs/distribution/RELEASE-1.20.0.md` in the form of `RELEASE-1.19.0.md`:
     behavior, validation, asset table, offline package refresh.
7. **Publish.** GitHub release `v1.20.0`, marked latest, titled "Marvin 1.20.0".
   - The body comes from `RELEASE-NOTES-1.20.0.md`.
   - The assets are the staged files under their public names, so the
     `releases/latest/download/...` links keep working.
   - Check every asset's size and digest against `release-1.20.0.json`, then add a
     "GitHub publication verification" section to the record. Commit and push to
     `main`.
8. **Delete old versions.**
   - Delete `dist\Marvin-Setup-1.19.0-*.exe` and `dist\release-1.19.0`.
   - Delete the 1.19.0 offline backup once the 1.20.0 backup has passed `verify`.
   - Older GitHub releases: the request does not say whether they go too, and a
